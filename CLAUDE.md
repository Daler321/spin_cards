# CLAUDE.md: SpinCards

Telegram Mini App: рулетка игровых банковских карт (монеты без денежного эквивалента). pnpm-монорепо
на TypeScript: `apps/api` (NestJS, Prisma, PostgreSQL, Redis, воркер), `apps/web` (Mini App),
`apps/bot` (grammY), `apps/admin`, `packages/game-core` (чистая логика), `packages/shared`, `infra`.

Начни с `docs/STATUS.md`; где лежит код — скилл `codebase-map`. Ищи только в области задачи. Для широкого поиска используй
Explore-сабагента. Не читай файлы целиком без необходимости. Правила папки — во вложенном
`CLAUDE.md` (`apps/*/CLAUDE.md`, `packages/*/CLAUDE.md`). Источник истины: код, скилл `codebase-map`,
`docs/decisions.md` (решения D-xxx). Начинай задачу с `/task`, заканчивай `/done`.

## Как работать

- Отвечать владельцу по-русски; код, комментарии, коммиты — по-английски (Conventional Commits).
- Перед задачей, которая трогает несколько областей, `packages/shared`, Prisma или экономику, —
  короткий план и подтверждение. Механику сверх запроса не придумывать.
- Пробел в требованиях: выбрать значение по умолчанию, записать в `docs/decisions.md`, сообщить.
- Прод (деплой, конфиг, флаги, данные): сначала проверить локально, спросить «Выкладываю на прод?»,
  делать только после явного «да». Одно «да» — на одну выкладку.
- Новые зависимости только по необходимости, крупную обосновать одним предложением. Баг сначала
  воспроизвести тестом. Крупный рефакторинг только по запросу.
- Только pnpm (не npm/yarn). Всё запускается в Docker; не требовать Postgres/Redis на хосте.

## Жёсткие правила

Игра и экономика:
- Решает только сервер: клиент не присылает шансы, результат, цену, тир. Рандом только
  `crypto.randomInt` на сервере, в game-core через интерфейс `rng`. Результат считается до анимации.
- Near-miss — только подсказка по выпавшему (флаг `near_miss_ux`); генератор не смещать, фальшивых
  остановок нет.
- Шансы не зависят от того, платил ли игрок. Различия только: пакет, карта оплаты, уровень, счётчики
  (удача, pity), скрытая стартовая удача новичков и малого баланса (только повышение, D-116).
- Все числа экономики — в версионируемом конфиге в БД; магических чисел в коде нет. Активация конфига
  только после симулятора (RTP 85–110 %).
- Без запроса владельца не делать: аукцион, друзья, шредер, краш-режим (заготовок в схеме нет). Крафт есть (D-170).
- Номер карты: первая цифра 9, не проходит Луна, нет реальных BIN; уникален среди `active`/`expired`
  внутри пары «банк + редкость» (D-123).

Деньги:
- Целые минимальные единицы, никаких float. Любое изменение баланса — запись в `ledger_entries` в той
  же транзакции, под блокировкой строки; баланс в таблице — кэш, равный сумме ledger.
- Каждая мутация идемпотентна (`idempotencyKey`) и атомарна. Валюты не смешиваются, обмен — отдельной
  операцией с комиссией. Никаких правок баланса SQL-ом или из админки без ledger и `audit_log`.

Безопасность:
- initData проверяется HMAC, срок ≤ 1 суток. `DEV_AUTH_BYPASS` только при `NODE_ENV=development`
  (prod не стартует с ним). Секреты только в `.env`: не коммитить, не логировать, маскировать.
- Rate limit и zod на каждом маршруте; наружу коды ошибок без стектрейсов. CORS только домены
  мини-аппа и админки. Админка: пароль + TOTP, роли, все действия в `audit_log`. Бот и админка без
  доступа к БД.

Данные:
- `season_id` обязателен в `spins`, `cards`, `leaderboard_snapshots`, `user_season_stats`, `events`.
- Схема только через Prisma Migrate, старые миграции не править. Ledger, spins, платежи не удалять.

Юридические рамки:
- Нет реальных названий банков, платёжных систем, логотипов, шрифтов, слоганов. На картах «игровая
  карта». Нет вывода реальных денег, Stars и TON. Шансы пакетов опубликованы. В текстах нет обещаний
  заработка и слова «казино».

Код:
- TypeScript strict, без `any` (исключение с `// why:`). Общие типы только из `packages/shared`.
  Тексты только через i18n (`common`, `game`, `shop`, `errors`, `bot`), ICU plural, `Intl`. Сервер
  отдаёт коды ошибок, не текст. Логи pino с `request_id`, без персональных данных.

## Команды

- `make up` / `make down` / `make logs s=api` — dev-стек; `make migrate`, `make seed`.
- `make check P=apps/web` — тихие lint + typecheck + тесты одного пакета.
- `make test`, `make lint`, `make typecheck`, `make format` — весь репозиторий.
- `make e2e` (при запущенном стеке), `make sim`, `make progression`, `make load-spin`.
- `make tunnel` (ngrok; `TUNNEL=cloudflared`), `make config-defaults` (только dev!), `make ledger-verify`.
- `make release` и `make ship HOST=…` — выкладка, см. `docs/deploy.md` и `docs/STATUS.md`.
