## Как работать с продом

- Деплой только после явного «да» владельца, каждый раз заново. Порядок: проверить локально →
  спросить «Выкладываю на прод?» → `git worktree add --detach <tmp>/rel main` → в нём
  `infra/scripts/release.sh` → `infra/scripts/ship.sh root@SERVER` → удалить worktree.
  `release.sh`, `ship.sh root@SERVER`, `ssh`/`scp` на сервер разрешены в
  `.claude/settings.local.json` (не в git): запускать одиночной командой из корня репо, без `cd … &&`
  и перенаправлений, иначе правило не совпадёт. `ship.sh` берёт тег из `infra/.release-tag`.
  Подробности: `docs/deploy.md`. Проверка после: `https://<домен>/api/health` (http даёт 308),
  логи api/worker без level 50/60, сверка ledger (SQL ниже).
- Чтение БД: SQL в файл → `scp` в `/tmp` → `docker compose --env-file .env --env-file release.env
-f compose.yml exec -T postgres sh -c "psql -U \$POSTGRES_USER -d \$POSTGRES_DB" < /tmp/x.sql`.
- Сверка ledger: балансы `wallets`/`cards` против `sum(delta)` из `ledger_entries` по
  `account_type, account_id` (должно быть 0 расхождений). Есть `make ledger-verify` (dev).
- Конфиг на проде НЕ через `./spincards.sh config-defaults`: он затирает правки из админки.
  Правка = новая версия от активной: разовый `.mjs` в `dist/` контейнера api с
  `AdminConfigService.createDraft → simulate → activate` (audit от аккаунта владельца с пометкой
  «by Claude on the owner's request»), потом удалить файл. Так сделаны v21 и v22. Полезно оформить
  постоянный CLI (долг).
- Долгие команды на сервере (симуляция ~1,5 мин) запускать через `nohup … &` и опрашивать лог:
  ssh рвётся.
- Разовые инструменты: `node dist/ops/season-launch-cli.js` (чистый старт сезона, D-149),
  `season-rename-cli.js --name … --reason …` (имя текущего сезона, D-160),
  `achievement-revoke-cli.js` (D-151), `region-merge-cli.js` (D-156); без `--confirm` только считают.
- Ручные правки игроков (обнуление и т. п.) только через ledger + `audit_log`, в одной транзакции с
  `lockPlayer`. Ledger, spins, payments не удалять никогда.

## Подводные камни окружения

- Всё в Docker: `node_modules` Linux лежат в named volumes; команды через `make` или
  `docker compose -f infra/docker-compose.yml -f infra/docker-compose.dev.yml run --rm --no-deps
tools …`. Для одного пакета: `make check P=apps/web`.
- Тесты api нужны Postgres и Redis (`make test` сам поднимает). Тестовая БД `spincards_test`;
  `test/support/global-setup.ts` меняет конфиг (стартовые 500 000 коп., без медалей и т. п.), поэтому
  в тестах брать числа из `GameConfigService.active()`, а не из `DEFAULT_GAME_CONFIG`.
- Параллельные сессии Claude работают в одной папке. Свою задачу вести в `git worktree` (scratchpad),
  туда скопировать игнорируемые `apps/api/src/generated/` и `.env` файлы; compose запускать с
  `-p spincards -f <worktree>/infra/…`. Перед коммитом проверять `git branch --show-current`.
- Shell в Claude Code (zsh): переменная со списком файлов или командой не делится на слова, нужен
  массив или скрипт-обёртка. Скрипты в `sh -c '…'` с `rm` блокирует проверка безопасности.
  Свои права (`.claude/settings*.json`) Claude менять не может: классификатор блокирует, просить владельца.
- После `schema.prisma` нужен `make migrate` (генерирует клиент в `apps/api/src/generated/`).
  Миграции и сиды применяются при старте api. Старые миграции не править.
- Бот в dev через long polling с тестовым токеном из `apps/bot/.env`; Mini App через
  `make tunnel` (ngrok, запасной cloudflared), `PUBLIC_URL` и адрес в BotFather. Админ dev `admin`
  не трогать. `DEV_AUTH_BYPASS` + `VITE_DEV_AUTH` только в development (e2e логинятся так).
- e2e (`make e2e`) идут против запущенного dev-стека через `proxy`; скриншоты пишутся в
  `apps/web/e2e-results/` (Playwright чистит папку при запуске).

## Хрупкие места

- Экономика: любые изменения шансов, лимитов, наград проверять симулятором; активация требует RTP
  85–110 % в сценариях regular и bestCard, 300 000 прокрутов (D-148). Полный дубль сильно шумит.
- `9777 7777 7777 7777` не выпадает: проходит Луна (D-148). Не «чинить» без решения владельца.
- Рейтинг в Redis: sorted set + hash `…:reached` (время достижения, D-154); при правке пересборки
  сохранять reached, иначе места при равенстве поедут.
- Медали и счётчики считать только по прокрутам текущего сезона (D-151, был баг с выплатой альфы).
- Стартовый холдер `basic` считается у всех всегда, даже без строки `user_holders` (D-150).
- Старт сезона и бонус за очки всегда в рублях, регион сбрасывается в RU (D-156); доллар — вторая
  валюта, переключатель в шапке.
- Рефералы: `dailyLimit = 0` значит без лимита (D-158). Риск твинков: следить за антифрод-сигналом.
- При git-слиянии соседних CSS-блоков git может «съесть» закрывающую `}`: после merge гонять lint.
- В тестах порядок игроков с равными очками решает возраст аккаунта: создавать последовательно.
