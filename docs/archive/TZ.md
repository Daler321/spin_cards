# ТЗ v1.1: SpinCards (Telegram Mini App)

> Рабочее название: **SpinCards** (генератор кредитных карт). Название может смениться, поэтому оно хранится в конфиге и i18n-ключах, а не размазано по коду.
> Документ предназначен для разработки через Claude Code. Работать по этапам из раздела 17. Каждый этап завершается рабочим состоянием и проверкой по критериям приёмки. Пункты **[ОТКРЫТО]** имеют значение по умолчанию, его можно менять.

## 0. Что изменилось относительно v1.0

- Два региона и две валюты (RUB и USD) с отдельными кошельками и конвертацией с комиссией; расширяемый справочник валют.
- У каждой карты свой баланс; платить за прокрут можно с кошелька или с карты, тир и редкость карты влияют на удачу.
- Карты уникальны: один номер не может быть одновременно у двух игроков; сгоревшие и обналиченные карты возвращаются в общий пул.
- Банки в стиле реальных банков РФ (жёлтый, синий, красный, зелёный), но только как ассоциация.
- Новые холдеры покупаются за валюту (с открытием по уровню) или за Stars (в любой момент).
- Оплата Stars: полная заготовка, выключена флагом.
- Сезоны заложены в схему БД.
- i18n с одним языком (ru), Docker для всего проекта, локальный запуск через туннель.
- Рейтинги: по балансу и по коллекции (редкость).
- Срок восстановления просроченной карты 3 суток, потом карта уходит в пул.
- Длинные лестницы цифр по всему номеру (например 1-8).

## 1. Цель версии

Рабочий прототип, который можно показать реальным пользователям и по метрикам понять, возвращаются ли они. Гипотеза: рулетка карт со сроком жизни, красивыми номерами и мягкой системой удачи даёт удержание D1 ≥ 35% и D7 ≥ 12%.

В v1 входит: ядро игры, дизайн карт и базовые анимации, база пользователей, отдельные backend / frontend / bot / admin, рейтинги, сохранение статистики, админка с метриками и управлением шансами, рефералка, ежедневные бонусы, холдеры, два региона/валюты, заготовка Stars и сезонов.

Не входит: аукцион и переводы между игроками, друзья, ачивки, шредер/крафт, краш-режим, шеринг картинкой, вывод реальных денег (его не будет вообще; возможный обмен на ценности внутри игры рассматривается только в будущем и не как вывод денег).

## 2. Принципы

1. Игровое решение принимает сервер. Результат известен до начала анимации; клиент только показывает.
2. Экономика (шансы, цены, лимиты, комиссии, сроки жизни, курсы) хранится в версионируемом конфиге в БД и правится из админки без деплоя.
3. Любое изменение баланса идёт через журнал операций (ledger). Баланс = сумма журнала, в таблицах хранится кэш.
4. Мутирующие операции идемпотентны (ключ идемпотентности) и выполняются в транзакции.
5. Шансы каждого пакета показываются игроку (экран «Шансы»).
6. **«Почти выпало»** допустимо только как честная подсказка по уже выпавшему результату (см. 4.8). Генератор не смещается в сторону «почти» и не показывает фальшивых остановок ленты.
7. Шансы не зависят от того, платил ли игрок и сколько. Различия в шансах задаются только пакетом, картой, с которой идёт оплата, уровнем и счётчиками активности.
8. Все строки интерфейса и бота идут через i18n-ключи; сервер возвращает коды ошибок, а не готовый текст.
9. Любая сущность, зависящая от периода (прокруты, карты, рейтинги, статистика), хранит `season_id`.
10. Экономика проверяется кодом: симулятор, юнит-тесты генератора, интеграционные тесты транзакций.

## 3. Архитектура и стек

Монорепозиторий (pnpm workspaces), TypeScript везде.

```
/apps
  /api       — backend (REST), бизнес-логика, джобы
  /web       — Telegram Mini App (игрок)
  /bot       — Telegram-бот (отдельный процесс)
  /admin     — админ-панель (отдельное SPA)
/packages
  /shared    — типы, zod-схемы, константы, i18n-ключи
  /game-core — чистая логика: генератор карт, паттерны номеров, оценка редкости, near-miss, симулятор (без I/O)
/infra       — docker-compose файлы, nginx/caddy, миграции, примеры .env
```

| Часть | Технологии (по умолчанию) |
|---|---|
| api | Node.js 20, NestJS (Fastify), Prisma, PostgreSQL 16, Redis 7, BullMQ, zod, pino |
| web | React 18, Vite, TypeScript, Zustand, TanStack Query, Framer Motion, `@telegram-apps/sdk`, i18next |
| bot | grammY (в dev long polling, в prod webhook), i18next |
| admin | React + Vite, Recharts, отдельная авторизация (логин/пароль + TOTP) |

Связь: web → api (HTTPS, JWT), admin → api (`/admin/*`, роли), bot ↔ api (внутренний токен). Бот и админка не пишут в БД напрямую, только через api.

## 4. Игровые сущности

### 4.1 Регионы, валюты, кошельки
- **Регион** переключается на главном экране: RU (карты в рублях, символ ₽) или US (карты в долларах, символ $). Регион определяет набор банков и валюту дропа.
- **Справочник валют** `currencies` (код, символ, знаков после запятой, активна ли). В v1 активны RUB и USD; добавление новой валюты не требует переделки схемы.
- **Кошелёк** у игрока по каждой валюте (`wallets`: user_id, currency, balance). Валюты не смешиваются.
- **Конвертация** между кошельками по курсу из конфига (по умолчанию 90 ₽ = 1 $, курс задаётся админом, живых курсов в v1 нет) с комиссией 3% (мин. комиссия и мин. сумма в конфиге, дневной лимит конвертации для защиты от арбитража при смене курса).
- Стартовый баланс нового игрока: 5 000 ₽ на рублёвом кошельке.
- Суммы хранятся целыми в минимальных единицах (копейки/центы) во избежание ошибок округления; на экране форматируются через `Intl.NumberFormat`.

### 4.2 Карта и её баланс
У каждой карты свой баланс (`balance`) в валюте карты. Баланс выпавшей карты = её стоимость (см. 4.7).

Поля: id, season_id, owner_id (nullable, если в пуле), bank_id, region, currency, tier, number, number_patterns (JSONB), rarity_score, base_limit, balance, initial_balance, luck_bonus (производное от тира и номера), status, owners_count, issued_at, expires_at, grace_until.

Статусы: `active` (у игрока), `expired` (льготное окно 3 суток), `pooled` (в общем пуле, без владельца), `cashed` (временный статус при обналичивании, затем `pooled`).

Что можно делать с картой:
- **Обналичить**: баланс карты переводится на кошелёк её валюты с комиссией, карта уходит в пул (см. 4.9).
- **Оставить в холдере** и **крутить с неё**: оплатить пакет балансом карты (5.2).
- **Пополнить** карту с кошелька той же валюты (без комиссии, нужно, чтобы крутить с выбранной карты). Частичного снятия с карты в v1 нет **[ОТКРЫТО]**.

### 4.3 Банки
По 4 банка на регион: цвет и стиль напоминают реальные банки, но без реальных названий, логотипов, шрифтов, слоганов и узнаваемых знаков. Ассоциация только через цвет, настроение и игру слов. Названия рабочие, меняются в конфиге **[ОТКРЫТО]**.

| Регион | Цвет | Рабочее название |
|---|---|---|
| RU | Жёлтый | «Лимон Банк» |
| RU | Синий | «Лазурь» |
| RU | Красный | «Рубин» |
| RU | Зелёный | «Изумруд» |
| US | Синий | «Liberty Trust» |
| US | Красный | «Eagle National» |
| US | Зелёный | «Evergreen» |
| US | Золотой | «Frontier Gold» |

Банк задаёт палитру, узор и логотип-заглушку (SVG, нарисован самостоятельно). Вес банков при выпадении равный (в конфиге).

### 4.4 Тиры

| Тир | Множитель дизайна | Срок жизни | Очки редкости | Бонус удачи при оплате с карты |
|---|---|---|---|---|
| Common | ×1.0 | 3 суток | 1 | +0% |
| Rare | ×1.5 | 5 суток | 3 | +3% |
| Epic | ×3.0 | 7 суток | 8 | +6% |
| Legendary | ×8.0 | 10 суток | 25 | +10% |
| Mythic | ×25.0 | 14 суток | 80 | +15% |

Все значения в конфиге (админка).

### 4.5 Номера карт
- 16 цифр, формат `XXXX XXXX XXXX XXXX`.
- Номер не проходит проверку Луна и не начинается с префиксов реальных платёжных систем: первая цифра всегда `9` (так не получится реальная карта, и это упрощает модерацию Telegram).
- Номер уникален среди всех карт, которые не в пуле (см. 4.9).
- Генерация идёт не «чисто случайно»: сначала по весам выбирается паттерн (или его отсутствие), потом номер достраивается случайными цифрами с проверкой уникальности.

### 4.6 Паттерны номера
Множители суммируются, итоговый множитель номера ограничен потолком (по умолчанию ×60). Все значения в конфиге.

| Паттерн | Пример | Множитель |
|---|---|---|
| Четыре одинаковых в блоке | 4444 | ×2.5 за блок |
| Радар (палиндром блока) | 1221 | ×2.0 за блок |
| Лестница в блоке | 1234 / 9876 | ×3.5 за блок |
| **Длинная лестница** по всему номеру (может пересекать блоки; вверх и вниз) | …12345678… | длина 5: ×5, 6: ×8, 7: ×15, 8: ×30, 9: ×60, 10: ×100 |
| Хвост 7777 | …7777 | ×12 |
| Хвост 0001 / 1337 | …0001 | ×8 |
| Хвост 6666 / 9999 | …6666 | ×5 |
| Полный дубль (16 одинаковых цифр) | 7777 7777 7777 7777 | ×100 и принудительно Mythic |

Правила: лестница считается максимальной длины и не считается повторно как короткая внутри себя; хвосты взаимоисключающие (берётся лучший). Полных дублей всего 10 возможных номеров, значит у них встроенный дефицит благодаря уникальности.

### 4.7 Стоимость и редкость карты
- `balance = floor(base_limit × design_mult × number_mult)`. Бонус удачи не увеличивает стоимость карты, он влияет только на шансы тира и паттерна (см. 5.2).
- `rarity_score = tier_points + Σ очков паттернов` (очки за паттерны в конфиге: четыре одинаковых 2, радар 1, лестница в блоке 3, длинная лестница по длине 5–60, хвост 7777 — 40, хвосты 0001/1337 — 25, хвосты 6666/9999 — 15, полный дубль — 500). Нужен для рейтинга коллекции и бонуса удачи.
- `luck_bonus` карты (при оплате с неё) = бонус тира + `min(rarity_score / 100, 0.10)`.

### 4.8 «Почти выпало» (честная подсказка)
Подсказка строится только по реально выпавшему номеру и не влияет на генерацию:
- номер отличается от элитного хвоста или паттерна ровно на одну цифру (например …7776, лестница 1-7 с нарушением на 8-й цифре, три из четырёх одинаковых);
- на экране результата показывается плашка вида «Почти 7777!» и лента замедляется на последних кадрах.

Правила: проверка выполняется в `game-core` на выпавшем результате; частота «почти» не регулируется и не повышается; включается и выключается флагом `near_miss_ux`; текст не обещает, что «в следующий раз повезёт».

### 4.9 Уникальность и общий пул
- Уникальность: частичный уникальный индекс по `number` для карт со статусами `active`, `expired`.
- Пул: обналиченные карты и карты, у которых истёк срок, переходят в `pooled`, теряют владельца и баланс (это сток экономики).
- Повторный дроп из пула: при прокруте с шансом `pool_redrop_chance` (по умолчанию 15%) и если в пуле есть карта выбранного тира и региона, выдаётся она (тот же номер и дизайн, новый баланс по обычным правилам, `owners_count + 1`). Так редкие номера циркулируют между игроками. Выдача из пула идёт по принципу «самая давняя первой».
- На карте отображается число владельцев («3-й владелец»), это коллекционная ценность.
- Админка показывает размер пула по тирам и паттернам.

## 5. Рулетка

### 5.1 Пакеты
Пакет задаёт цену (по валютам), диапазон базового лимита и шансы тиров; шансы одинаковы для всех игроков и не зависят от способа оплаты. У пакета могут быть цена в валюте и цена в Stars (или только Stars).

| Пакет | Цена ₽ | Цена $ | Цена ⭐ | Диапазон base_limit (₽) | Шансы C/R/E/L/M, % |
|---|---|---|---|---|---|
| Бесплатный (по таймеру) | 0 | 0 | — | 200–600 | 88 / 10 / 1.8 / 0.2 / 0 |
| Базовый | 1 000 | 12 | — | 300–900 | 85 / 12 / 2.8 / 0.2 / 0 |
| Бизнес | 15 000 | 170 | — | 8 000–13 000 | 50 / 35 / 12 / 2.8 / 0.2 |
| Премиум | 100 000 | 1 100 | — | 60 000–90 000 | 10 / 45 / 30 / 13 / 2 |
| VIP (заготовка) | — | — | 50 | 40 000–150 000 | 0 / 0 / 60 / 32 / 8 |

Диапазоны в долларах задаются в конфиге явно (при создании конфига пересчитываются по курсу и округляются). VIP-пакет выключен флагом `stars_enabled=false` и скрыт в интерфейсе.

Ответ на вопрос «влияет ли способ оплаты на удачу»: да, но через **пакет**, а не через игрока. Пакет, купленный за Stars, может иметь лучшие опубликованные шансы, но они одинаковы для всех, кто его открывает. Оплата валютой и оплата Stars одного и того же пакета дают одинаковые шансы.

### 5.2 Оплата прокрута и влияние на удачу
Оплатить пакет можно:
- **с кошелька** региона (нейтральная оплата, без бонуса);
- **с карты** из холдера той же валюты, у которой хватает баланса. Карта даёт бонус удачи `luck_bonus` (см. 4.7): увеличивает вес Rare+ тиров (в пределах общего потолка бафов) и вероятность паттерна в номере. Баланс карты уменьшается на цену пакета.

Игрок выбирает «чем платить» перед прокрутом (список карт с балансом, тиром и бонусом удачи). На экране виден итоговый бонус удачи перед нажатием кнопки.

### 5.3 После выпадения новой карты
- **Обналичить**: `payout = balance × (1 − fee)`, зачисляется на кошелёк валюты карты, карта уходит в пул. Комиссия по умолчанию 10%, с ростом уровня снижается (−0.5% за уровень, минимум 2%).
- **В холдер**: карта остаётся у игрока. Если слоты заполнены, нужно обналичить другую карту, освободить слот или купить новый холдер.

### 5.4 Холдеры (слоты)
Холдер это покупаемый предмет, дающий слоты. Слоты складываются.

| Холдер | Слоты | Открывается с уровня | Цена ₽ / $ | Цена ⭐ (в любой момент) |
|---|---|---|---|---|
| Базовый | 5 | 1 | бесплатно | — |
| Кожаный | +5 | 4 | 20 000 / 230 | 40 |
| Стальной | +10 | 9 | 120 000 / 1 350 | 120 |
| Золотой | +20 | 15 | 600 000 / 6 700 | 300 |

Покупка за валюту доступна с указанного уровня, за Stars в любой момент (когда включён флаг `stars_enabled`). Таблица в конфиге.

### 5.5 Мягкая система удачи (удержание)
Цель: честный рандом, но со сглаживанием дисперсии. Всё настраивается в конфиге.

1. **Шкала удачи** (0–30): каждый прокрут +1. На 30/30 следующий прокрут «Счастливый»: веса Epic+ ×2 с последующей нормализацией. Шкала сбрасывается.
2. **Гарантии (pity)** по пакету и пользователю: Rare+ не реже чем раз в 8 прокрутов, Epic+ раз в 40, Legendary+ раз в 250 (для Бизнес/Премиум). Сработавшая гарантия сбрасывает свой счётчик.
3. **Сценарий новичка**: первые 5 прокрутов по таблице тиров (1-й Rare, 2-й Common, 3-й Epic, 4–5-й случайные с небольшим бонусом). Паттерн номера на этих прокрутах тоже может выпасть.
4. **Возвращение**: пауза ≥ 3 суток → следующий бесплатный прокрут «Счастливый» и уведомление от бота.
5. **Серия неудач**: после 6 подряд прокрутов с результатом ниже цены пакета +5 очков шкалы удачи (веса не меняются напрямую).
6. **Бафы удачи** (ежедневная награда, магазин, сундучки): +X% к весам Rare+ на M прокрутов.
7. **Общий потолок** прибавки от карты, бафов и «Счастливого» (по умолчанию +50% к исходным весам Rare+).

### 5.6 Алгоритм прокрута (сервер)
1. Проверить идемпотентность, способ оплаты и баланс/право на бесплатный прокрут; списать цену (запись в ledger, источник: кошелёк или карта).
2. Собрать эффективные веса: базовые → «Счастливый» → бонус карты → бафы → потолок → нормализация.
3. Применить гарантии и сценарий новичка (приоритет над случайностью).
4. Выбрать тир (`crypto.randomInt`), банк региона, базовый лимит в диапазоне.
5. Источник карты: с шансом `pool_redrop_chance` взять карту из пула нужного тира; иначе сгенерировать номер (4.5, 4.6) с проверкой уникальности (до 10 попыток, затем увеличить шанс обычного номера).
6. Посчитать баланс, редкость, срок жизни, near-miss подсказку; сохранить карту и запись `spin` (параметры, версия конфига, season_id, источник оплаты).
7. Обновить счётчики (pity, шкала, статистика, EXP) и вернуть готовый результат клиенту.

### 5.7 Таймер бесплатных прокрутов
Один бесплатный прокрут каждые 4 часа, накапливается до 3. Бот уведомляет о готовности (не чаще раза в 8 часов, отключаемо).

### 5.8 Симулятор экономики (`game-core`, доступен в админке)
Прогон N (до 1 млн) виртуальных прокрутов с конфигом-кандидатом, включая оплату с карт и повторные дропы из пула: распределение тиров, среднее значение баланса, RTP при немедленном обналичивании (с комиссией), частота паттернов и near-miss, 99-й перцентиль, длины серий без Rare+/Epic+. Админка не даёт активировать конфиг без симуляции, а симуляция должна укладываться в коридор RTP (по умолчанию 85–105%).

## 6. Срок жизни карты

- Карта живёт `lifespan` суток по тиру (4.4) с момента выпадения.
- По истечении срока статус `expired` и льготное окно **3 суток**: карту можно **восстановить** за 25% от баланса либо обналичить со штрафной комиссией 20%.
- Не восстановлена и не обналичена за 3 суток: выкуп невозможен, баланс сгорает, карта возвращается в общий пул.
- **Продление** до истечения: 10% от баланса, срок +50% исходного, максимум один раз.
- Уведомления ботом за 24 часа и за 3 часа до истечения (для карт выше порога баланса или редкости).
- Просроченную (`expired`) карту нельзя использовать для оплаты прокрутов.
- Джоба переводит статусы каждую минуту.

## 7. Игроки, уровни, рейтинги

### 7.1 Пользователь
Создаётся при первом входе по Telegram `initData` (HMAC-проверка на сервере, срок годности ≤ 1 суток). Поля: telegram_id, username, first_name, language, photo_url, region, exp, level, referrer_id, created_at, last_seen_at, is_banned, настройки уведомлений, experiment_group.

### 7.2 Уровни
Таблица в конфиге: уровень → EXP → награды (слоты/холдеры, снижение комиссии, открытие пакетов и холдеров, бафы). EXP за прокруты (по цене пакета), ежедневный вход, редкие карты. Уровней в v1: 20; «Бизнес» открывается с 3-го, «Премиум» с 8-го.

### 7.3 Рейтинги (по сезону, Redis sorted sets, снимок раз в 5 минут в БД)
- **По балансу**: сумма кошельков, приведённая к рублю по курсу из конфига. Стоимость карт не учитывается.
- **По коллекции**: сумма `rarity_score` активных карт игрока (учитывает тир и паттерны номера, но не баланс карт).

Экран «Рейтинг»: топ-100, своё место, переключатель типа. Игрок может скрыть себя из рейтинга в настройках.

## 8. Бонусы и рефералка

- **Ежедневный вход**: серия на 7 дней (валюта, бафы удачи, бесплатные прокруты, на 7-й день гарантированный Epic+). Пропуск сбрасывает серию, одно «прощение» в неделю.
- **Сундучок**: каждые 10 прокрутов, содержит валюту или баф.
- **Магазин за валюту**: бафы удачи (3 размера), пакеты бесплатных прокрутов, продление и восстановление карт, холдеры.
- **Рефералка**: ссылка `t.me/<bot>?startapp=ref_<code>`. Награда обоим начисляется, когда приглашённый сделал 5 прокрутов и достиг 2-го уровня. Дневной лимит рефералов на аккаунт; награды в конфиге.

## 9. Оплата Telegram Stars (заготовка, выключена)

Флаг `stars_enabled=false`. Всё ниже реализуется и тестируется в тестовом окружении, но скрыто в интерфейсе:
- Таблицы `star_products` (товар: пакет, холдер, набор валюты, бафы, цена в ⭐), `payments` (статус, telegram_payment_charge_id, суммы, идемпотентность).
- Создание ссылки на инвойс (`createInvoiceLink`, валюта `XTR`) в api, открытие во фронте через `Telegram.WebApp.openInvoice`.
- Бот обрабатывает `pre_checkout_query` (проверка товара и пользователя) и `successful_payment` (зачисление товара через ledger, идемпотентно).
- Возврат через `refundStarPayment` из админки с откатом товара.
- Правила: только цифровые товары внутри игры, шансы пакетов публикуются, без «усиления шансов» под конкретного игрока.

## 10. Сезоны (заложить в базу, не реализовывать механику)

- Таблица `seasons` (id, название, старт, конец, статус, ссылка на набор дизайнов/конфиг).
- `season_id` обязателен в `spins`, `cards`, `leaderboard_snapshots`, `user_season_stats`, `events`.
- В v1 существует один сезон «Бета» без даты окончания, все записи привязаны к нему.
- Заложить в конфиге `design_sets` (наборы дизайнов по сезонам) и поле `season_only` у дизайнов.
- Правила перехода между сезонами (что переносится, что сбрасывается, награды за итоги) в v1 не реализуются **[ОТКРЫТО]**.

POST /v1/cards/:id/cashout

POST /v1/cards/:id/topup            — пополнить с кошелька
POST /v1/cards/:id/extend
POST /v1/cards/:id/restore
GET  /v1/cards                      — холдер
POST /v1/wallet/convert             — конвертация валют

### 11.2 Внутренние маршруты бота
`/internal/bot/*` (события пользователя, очередь уведомлений, обработка платежей), защищены внутренним токеном и сетью.

### 11.3 Админские маршруты (`/admin/*`, роли `owner`, `analyst`, `support`)
Метрики, конфиги (версии, симуляция, активация, откат), пользователи, рассылки, пул карт, флаги, сезоны (просмотр), платежи (заготовка), audit_log.

### 11.4 Безопасность
- Валидация initData (HMAC), JWT, rate limit (Redis), идемпотентность.
- Серверный рандом; клиент не присылает ни шансов, ни результатов.
- Блокировки строк (`SELECT … FOR UPDATE`) на кошельки и карты при списании.
- Предохранитель дневной эмиссии, бан пользователей, аудит ручных операций.
- CORS только с домена мини-аппа и админки, секреты только в env.
- Режим разработки `DEV_AUTH_BYPASS` (мок-пользователь без подписи Telegram) разрешён только при `NODE_ENV=development`, в production приложение не стартует с этим флагом.

## 12. База данных (PostgreSQL)

Основные таблицы (индексы по внешним ключам и датам):

Миграции через Prisma Migrate. Сиды: дефолтный конфиг, 20 уровней, банки, холдеры, валюты, один сезон, админ owner.

## 13. Frontend (Mini App)

Мобильный вертикальный интерфейс, тёмная тема, цвета Telegram, `Telegram.WebApp.ready/expand`, кнопка «Назад», haptic feedback.

### Экраны
1. **Рулетка** (главный): шапка (аватар, уровень/EXP, баланс выбранной валюты, переключатель региона RU/US), лента карт, шкала удачи, выбор пакета, выбор «чем платить» (кошелёк или карта) с итоговым бонусом удачи, кнопка «Выпустить карту», таймер бесплатного прокрута. После результата кнопки «Обналичить за X» и «В холдер», плашка «почти выпало» при наличии.
2. **Холдер**: веер карт, детальный просмотр (баланс, тир, редкость, число владельцев, таймер жизни), пополнить/продлить/восстановить/обналичить, слоты X/Y, покупка холдера.
3. **Кошелёк**: балансы по валютам, конвертация, история операций.
4. **Рейтинг**: по балансу и по коллекции, своё место.
5. **Бонусы**: серия, сундучок, магазин.
6. **Профиль**: статистика, реферальная ссылка, настройки, экран «Шансы».
7. **Онбординг**: 3 коротких экрана перед первым прокрутом.

### Дизайн и анимации
- Компонент `<Card>` (слои: фон тира, узор и цвет банка, голограмма, чип, номер, имя, срок, плашка тира). Тир определяет материал: Common матовый серый, Rare неон, Epic золото, Legendary платина с голографией, Mythic чёрный шёлк с переливом. Банк определяет палитру и узор, поэтому комбинаций банк × тир по 4 × 5 на регион.
- Паттерны номера подсвечиваются (пульс/золото), длинные лестницы выделяются цепочкой.
- Наклон карты по гироскопу (iOS с запросом разрешения, запасной вариант: наклон от касания).
- Анимации (Framer Motion): лента карт с замедлением, вылет карты, вспышка по тиру, счётчик баланса, «улёт» в холдер, рассыпание купюр при обналичивании. Пропускаются тапом, отключаются при `prefers-reduced-motion`.
- Звуки по умолчанию выключены.
- Все ассеты карт (SVG/CSS), без сторонних картинок.

### i18n
`i18next`, пространства имён (`common`, `game`, `shop`, `errors`, `bot`), все строки через ключи, язык по умолчанию `ru`, определение языка пользователя из Telegram, запасной язык `ru`. Форматы чисел/дат/валют через `Intl`. Склонения через ICU plural. Сервер возвращает коды ошибок, текст подставляет клиент.

## 15. Админка

Отдельное SPA: логин/пароль + TOTP, роли.

### 15.1 Метрики
- Аудитория: новые, DAU/WAU/MAU, retention D1/D7/D30 (когорты), сессии на пользователя.

### 15.2 Управление шансами и экономикой
- Редактор конфига (формы и JSON): пакеты и цены по валютам и Stars, веса тиров, диапазоны лимитов, множители дизайна и паттернов, потолки, комиссии, сроки жизни, окно восстановления, курс и комиссия конвертации, параметры удачи (шкала, pity, бонусы тиров, потолок), `pool_redrop_chance`, холдеры, уровни, награды, цены магазина.

- Заготовка A/B: у пользователя `experiment_group`, к группе можно привязать версию конфига (минимальный UI).

## 16. Окружение, Docker, локальный запуск

Весь проект запускается в Docker.

- `infra/docker-compose.yml` (общие сервисы) и `docker-compose.dev.yml` (hot reload через bind mount), `docker-compose.prod.yml` (собранные образы).
- Сервисы: `postgres`, `redis`, `api`, `worker` (джобы), `web`, `admin`, `bot`, `proxy` (Caddy/Nginx, единая точка входа, маршруты `/`, `/admin`, `/api`).
- Мультистейдж `Dockerfile` для каждого приложения, healthchecks, миграции и сиды автоматически при старте (`api`), volume для данных Postgres.
- `Makefile` или pnpm-скрипты: `make up`, `make down`, `make logs`, `make migrate`, `make seed`, `make test`, `make sim` (запуск симулятора), `make tunnel`.
- `.env.example` для каждого приложения, секреты не коммитятся.
- Dev-режим бота: long polling, поэтому публичный адрес нужен только для Mini App.

### Доступ из Telegram без домена (до покупки домена)
Mini App обязан открываться по HTTPS. Варианты, по убыванию удобства:
1. **Cloudflare Tunnel (`cloudflared`)**: бесплатный быстрый туннель `cloudflared tunnel --url http://proxy:80`, стабильнее и без лимитов показа промежуточной страницы. Добавить как сервис с профилем `tunnel` в compose.
2. **ngrok**: подходит, но на бесплатном плане URL меняется при перезапуске (нужно обновлять адрес в BotFather) и бывает страница-предупреждение.
3. **localtunnel / tuna / serveo**: запасные варианты, менее стабильны.
4. Telegram **тестовая среда** (test DC) для проверки без production-бота.

После получения URL нужно задать его в BotFather как адрес Mini App (меню бота) и в переменной `PUBLIC_URL`. Для отладки в обычном браузере использовать `DEV_AUTH_BYPASS`.

### Общая приёмка v1
- Новый пользователь проходит онбординг, делает прокрут, обналичивает или сохраняет карту, платит прокрут картой, конвертирует валюту, видит рейтинги, получает ежедневный бонус и бесплатный прокрут по таймеру.
- Номер карты не может принадлежать двум игрокам одновременно; обналиченная или сгоревшая карта попадает в пул и может выпасть другому игроку.
- Админ меняет шансы через новую версию конфига, видит отчёт симуляции, активирует, видит эффект в метриках, откатывает.
- Бот шлёт уведомления и принимает реферальные ссылки.
- Баланс любого кошелька и любой карты восстановим из ledger. Повторный запрос не списывает дважды.
- Включение `stars_enabled` в тестовой среде проводит покупку Stars-товара и возврат без ошибок баланса.
- Весь проект поднимается одной командой в Docker, Mini App открывается из Telegram через туннель.
- Реальных названий и логотипов банков нет, номера карт не проходят проверку Луна.

## 18. Нефункциональные требования

- p95 `/spin` ≤ 300 мс, остальные ≤ 200 мс.
- Android 8+/iOS 14+, актуальный Telegram, 60 fps анимаций на среднем телефоне.
- Бандл Mini App ≤ 500 КБ gzip (без ассетов), ленивая загрузка экранов.
- Структурированные логи (pino), `request_id`, ежедневные бэкапы БД с проверкой восстановления.

## 19. Юридические и модерационные рамки

- Игра развлекательная; монеты и карты не имеют денежного эквивалента, вывода реальных денег, Stars и TON нет и не будет. Это прописано в правилах.
- Платные покупки (после включения) только через Telegram Stars и только цифровые товары внутри игры; шансы пакетов публикуются.
- Банки-пародии: только цвет и стиль, без реальных названий, логотипов, шрифтов, слоганов и узнаваемых знаков; названия не должны звучать как реальные.
- Номера не проходят проверку Луна и не имеют реальных префиксов; на картах стоит пометка «игровая карта».
- Страницы правил и политики конфиденциальности (данные: Telegram id, ник, действия в игре) доступны в боте и профиле.
- Возрастная метка 18+ в описании бота **[ОТКРЫТО]**. Рекламные тексты без обещаний заработка.

## 21. Рекомендации по работе с Claude Code

1. Положить файл в корень репозитория как `TZ.md`; в `CLAUDE.md` вынести правила: структура монорепо, команды, принципы из раздела 2, запрет менять баланс мимо ledger, запрет игровой логики на клиенте, запрет хардкодить строки и числа экономики.
2. Каждый этап начинать в режиме плана: «Прочитай TZ.md, раздел X, составь план этапа M#, дождись подтверждения».
3. Сначала `game-core` и тесты: на нём держится экономика. Не идти в UI, пока симулятор не показывает адекватный RTP.
4. После каждого этапа: тесты, коммит, запись в `CHANGELOG.md`.
5. Секреты (токен бота, JWT-секрет) только через `.env`.
